# 証憑研究版の評価JSON集計ツール

保存済みの評価JSONから、項目別の正解率、確認が必要な件数、データの来歴を表示する研究用ツールです。証憑画像を読み取る機能は含みません。

この配布物は、選択した`metric_layers.py`に入力形式の検査を加えた版です。元の研究リポジトリのコードと利用条件は変更していません。

## このPCで例を確認する

Python 3.10以降で、展開したフォルダーから実行してください。追加ライブラリ、APIキー、モデル、フォントの取得は不要です。

```powershell
python -B -X utf8 metric_layers.py examples/synthetic-result.json --json
python -B -X utf8 metric_layers.py examples/synthetic-result.json
```

例は、入力形式と出力を確認するために作った架空の2件です。モデルの試験結果や本人の業務成果を表す数値ではありません。所要時間とモデルの来歴は未入力です。期待する出力は[例の確認事項](examples/EXPECTED.md)を参照してください。

## 入力を確認してから集計する

入力は`summary`を持つJSONオブジェクトです。`summary.cases`または`results`が必要です。項目抽出では`summary.field_accuracy`、照合では`summary.match_accuracy`を使用します。`results`がある場合は配列にしてください。

率は0から1までの有限の数値で指定します。たとえば、正解率90％は`0.9`です。`2`、`NaN`、`Infinity`、数値に見える文字列、真偽値を率として渡すとエラーになります。

各結果の`correct`と`match`内の正誤は、JSONの`true`または`false`で指定してください。引用符を付けた`"false"`は文字列なので受け付けません。`correct`が未入力の結果は、従来どおり正解として数えません。

JSONの同じオブジェクト内で、項目名を重複させないでください。`match_accuracy`や`correct`が2回ある場合は、どちらの値も選ばずに停止します。同じ値を2回書いた場合や、Unicodeのエスケープ表記を使って同じ項目名にした場合も対象です。異なる結果のオブジェクトがそれぞれ`correct`を持つ正常な形式は、そのまま集計できます。

件数は0以上の整数、所要秒数は0以上の有限の数値にしてください。文書の種類・方法・ファイル名・状態を指定する場合は文字列を使用します。不正な項目があれば、その項目名や何件目かを標準エラー出力に表示し、集計前に終了コード1で停止します。途中までの集計結果は標準出力に出しません。ファイルを開けない場合も終了コード1です。

集計値の一部は入力の`summary`をそのまま表示します。正解ラベルや元画像を検証する処理はなく、件数、率、来歴の完全な整合性検査も行いません。利用者は入力の出どころと計算方法を別途確認してください。個人情報や顧客資料を公開リポジトリへ追加しないでください。

評価対象が0件の場合は、正解率に`1`（100％）が記載されていても`pass`にしません。`quality_gate.status`は`human_review_required`、理由は`no_cases`になります。`summary.cases`を省略して空の`results`を渡した場合も対象です。空の結果も集計して表示しますが、確認が必要な状態として扱います。件数が1件以上で、`summary`だけを渡す既存の形式はそのまま使えます。

`quality_gate.status`が`human_review_required`なら、結果を確認してください。この状態でもCLIの終了コードは0です。自動処理では終了コードだけで採用せず、JSONの状態を読む必要があります。`pass`も、入力に記載された率などがこのツールの条件を満たしたという意味です。証憑や正解ラベルの正しさを保証するものではありません。

## 修正を手元で確かめる

展開したフォルダーで、入力不備と既存の出力を確かめる35件の試験を実行できます。試験は架空の入力だけを使い、外部APIへ接続しません。

```powershell
python -B -X utf8 -m unittest -v
```
